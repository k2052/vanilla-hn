* 0. Executive Summary

Vanilla HN is a deliberately framework-free Hacker News client built to
illustrate the problems that React et al. solve. It works, but it has
been allowed to drift: the toolchain is stuck on Babel 6 / ESLint 7 /
webpack-4-era plugins, several modules contain real bugs, and only a
handful of files have tests. The plan below keeps the *spirit* of the
project (template-string components, async-generator sagas, a hand-rolled
store, no virtual DOM) while:

  1. Replacing the webpack + Babel + ESLint + Prettier + PostCSS-cssnext
     toolchain with a modern, minimal stack: **Vite** (dev server, client
     build, SSR build) and **Biome** (lint + format in one tool). Tests
     move to **Vitest**, the idiomatic runner for a Vite project.
  2. Dropping Babel entirely — Vite uses esbuild for transforms and the
     target is Node 20+ / evergreen browsers, so async generators and all
     syntax used here are native. No transpile step, no =babel-eslint=.
  3. Migrating off the deprecated Firebase compat import to the modular
     v11+ SDK (behind a tiny injectable =hnApi= interface) so the data
     layer actually runs on Node 20+.
  4. Fixing a set of correctness bugs discovered during analysis.
  5. Closing security holes (unescaped HTML interpolation).
  6. Taking test coverage from ~5% of files to effectively 100% of the
     universal + client + server layers, with the network fully mocked.

The work is organized into *phases* that are each independently
shippable. Each phase ends green (biome check + type-check + tests pass).
No phase is allowed to leave the tree red.

** 1.3 Correctness bugs found in source
- =src/universal/pages/Newest.js= fetches ='newstories'= — verify the
  HN API endpoint name against https://github.com/HackerNews/API; fix to
  the documented name if wrong.
- =src/universal/pages/Show.js= and =Newest.js= both declare their
  component as =const News = ...= (copy-paste from News). The export is
  correct but the local name is misleading; rename to =Show=/=Newest=.
- =getStories= slicing: =end = (start + max) - 1= then =.slice(start, end)=
  returns =max-1= items (slice end is exclusive). Should be =start + max=.
- =Stories.js= "More" link hardcodes =/news?page=${page+1}= on *every*
  list page (ask/show/jobs/newest all paginate to /news).
- =routeChange.js= uses =window.location.query= which does not exist on
  the Location interface; client initial query is always ={}=.
- =client/index.js= initial state reads =window.location.query= (same bug).
- =Link.js= / =StoryComment.js= handler IDs:
  =randLetter + Date.now()= is not guaranteed unique and is *never cleaned
  up* — handlers leak onto =window= forever and collide on rapid clicks.
- =StoryComment.js= toggle effect: =client/effects/index.js=
  =toggleComment= calls =StoryComment(comment)= *directly*, bypassing the
  =wrap= HOC, so =toggledComments= is =undefined= inside the re-render and
  =toggledComments[id]= throws when collapsing a top-level comment.
- =StoryComment.js= child recursion passes =parent: false= and a
  =toggled= flag that is *never read* when =parent= is false — dead code.
- =getComments.js= recurses with no depth guard; a deep comment thread
  spawns an unbounded fan-out of Firebase reads (and can blow the stack
  on a malformed item).
- =db.js= uses =import firebase from 'firebase'= — the legacy compat
  default export was removed in the modular SDK; this does not work with
  =firebase@11= at all.
- =timeAgo.js= regex =/[a-z]+/= only replaces the first alpha run; values
  like ="1.5h"= work but anything with a unit prefix breaks silently. Also
  =ms()= can return plain numbers for very small diffs (no unit to map).
- =server/index.js= TODO comment: "Make this vanilla node http code" —
  current Koa usage is fine but =koa-mount: "next"= is a nonsense version
  pin and should be a real semver range.

** 1.4 Security issues (XSS)
Every component interpolates HN-controlled text directly into HTML:
  - =Story.js=: =title=, =user=, =host= (derived from URL — mostly safe)
  - =StoryComment.js=: =text= (HN returns HTML; we drop it in raw), =user=
  - =Meta.js=, =Header.js=, etc. are static.
There is *no escaping anywhere*. A title or username containing
=<script>= or =">= breaks the page and executes arbitrary script. This
must be fixed with a small =escapeHtml= helper applied at every
interpolation of untrusted data, plus a decision about HN's pre-rendered
comment HTML (sanitise via a tiny allowlist, or strip tags).

** 1.5 Code-quality / maintainability smells
- Inconsistent return styles; some components use parens around template
  literals, some don't.
- =eslint-disable-line= sprinkled for =no-console= and unused =e=; the
  rules are wrong, not the code (catch =e= should be logged or rethrown).
- =Store.dispatch= swallows nothing, but =runEffect= does =console.log(e)=
  on effect failure — errors vanish in production.
- =wrap.js= reaches into =root.store.state= by string path at call time;
  tight coupling to a global that is only set on the server in one place.
- No TypeScript / JSDoc typing — components accept untyped bags.
- =serve=, =switch-path-ruta3=, =gh-pages= etc. — verify each is still
  used; =serve= appears unused.
- Two lockfiles; CI indeterminism.

* 2. Target Architecture (what we are *not* changing)
To respect the project's purpose, the *shape* of the code stays:
  - Components = (state) => HTML string.
  - Events = plain objects with =type= + =payload=.
  - Sagas = async generators yielding effects.
  - Effects = async (store) => store functions with =.meta.type=.
  - Store = plain-object state + saga dispatch + effect runner.
  - Routing = =switch-path= over a route map.
  - SSR via a tiny Koa (or plain http) server.

What *does* change: the build that produces this code, the data adapter,
escaping, error handling, and the test harness. Notably the app still
ships **no virtual DOM, no frontend framework, no JSX** — Vite and Biome
are *tooling*, not runtime frameworks, so the "vanilla" thesis holds.

** Phase 2 — Fix the data layer (Firebase)
The app cannot run on Node 20+ until this is done.

*** 2.1 Choose adapter strategy
Decision: introduce a thin =hnApi= module behind an interface, with two
implementations:
  1. =hnApi/firebase.js= using the *modular* =firebase/database= SDK
     (=import { initializeApp } from 'firebase/app'; import { getDatabase, ref, get, onValue, off } from 'firebase/database'=).
  2. =hnApi/rest.js= using the official HN REST-ish endpoint
     (https://hn.algolia.com/api or the Firebase REST JSON) — used in
     tests and as a fallback so the test suite never touches the network.

This isolates the Firebase upgrade behind one module and makes the whole
app mockable.

*** 2.2 Refactor =lib/db.js=, =getStories=, =getItem=, =getComments=
- [X] Rewrite =db.js= with the modular SDK; export =once(path)= and
  =on(path, cb)= / =off(handle)= primitives, not a raw ref.
- [X] =getItem=: keep =transform= + =observe= exports; =observe= uses
  =on()=.
- [X] =getStories=: fix the off-by-one slice (Phase-3 item, but do it here
  while we're in the file) and add input validation (page >= 1).
- [X] =getComments=: add a =maxDepth= option (default 10) to bound
  recursion; convert to an explicit stack to avoid deep recursion.

*** 2.3 Make the network injectable
- [X] All =lib/= functions take an optional ={ api }= param defaulting to
  the firebase adapter, so tests pass a fake.
- [X] Pages receive =api= from a single =createApp({ api })= factory used
  by both server and client. This replaces the global =root.store=
  pattern in =wrap.js= (Phase 3).

Exit criteria: SSR + client boot against the real Firebase succeed; tests

* 5. Risks & Mitigations
| Risk                                          | Mitigation                                              |
|-----------------------------------------------+--------------------------------------------------------|
| Vite SSR for a non-framework app is unusual   | Keep SSR trivial: =view(state)= returns a string;     |
| (no React plugin)                             | Vite just bundles + serves =src/server=. Document     |
|                                               | that Vite/Biome are tooling, not runtime frameworks.   |
| Asset hashing breaks =main.js= hardcoded     | Read =dist/.vite/manifest.json= in =main.js= in prod;  |
| =bundle.js=/=main.css= references             | dev falls back to =/src/client/index.js=.              |
| Event-delegation refactor feels "less vanilla"| Keep =Link= / =StoryComment= markup identical; only   |
|                                               | the wiring moves. Document as "what a vDOM gives you". |
| =sanitize-html= is a dep                      | Justify as security-critical; alternatively hand-roll.  |
| Firebase modular SDK behaviour differs        | Adapter isolation (Phase 2) + integration test against  |
|                                               | the real API in CI behind an env flag, optional.       |
| Coverage thresholds block PRs                 | Land coverage incrementally per Phase-4 sub-items;     |
|                                               | set thresholds to *current* coverage first, ratchet up.|
| Biome lacks a rule we relied on from airbnb   | Biome's recommended set is opinionated; add targeted   |
|                                               | rules or accept the simpler policy (the codebase is   |
|                                               | small). Audit the diff on the format commit.           |
| Removing Babel reveals latent syntax bugs     | Phase 1 build runs before any source edits; esbuild is |
|                                               | stricter than Babel 6 — fix on the toolchain PR only.  |
